# DNIIP — Distributed Network Incident Investigation Platform

A C++20 / Linux system programming observability platform: agents collect
telemetry from `/proc`, ship it over a custom epoll-multiplexed TCP
protocol, and a server-side pipeline correlates failures into incidents
with generated root-cause-analysis reports, surfaced in a React dashboard.

## Status (feature-complete against the original spec, fully verified)

The entire stack — including the Linux-only `dniip-agent`/`dniip-server`
(built on this dev machine, macOS, via Colima) — has been built, brought up
with `docker compose`, and exercised for real: real TCP connections over
the real `epoll` server, real telemetry reaching real PostgreSQL, real
Prometheus scrapes, and the dashboard clicked through in a real browser
against the live containerized stack. `tests/integration/run_integration_test.sh`
passed all assertions end-to-end. Three real bugs were found and fixed in
the process — see the git history for `docker/Dockerfile.*` and
`server/CMakeLists.txt` (missing `scripts/` in the Docker build context;
Debian's older CMake only providing the `SQLite::SQLite3` target, not the
newer `SQLite3::SQLite3` alias; and a Grafana dashboards volume nested
inside a read-only provisioning mount).

Built and tested now:
- **Wire protocol** (`common/protocol.hpp`, `common/telemetry.hpp`): length-prefixed JSON framing. Documented in `docs/protocol.md`.
- **Agent** (`agent/`): CPU/memory/network collectors reading `/proc`, TCP retransmit counting from `/proc/net/snmp`, ICMP ping + gateway + DNS diagnostics via raw sockets/`getaddrinfo`, SQLite store-and-forward buffer, blocking TCP client, signal-handled 30s collection loop.
- **Server** (`server/`): `epoll`-based TCP collector, producer/consumer queue, rule-based correlation engine (4 rules), incident engine, RCA engine with recommendation lookup.
- **Persistence** (`server/database/`): backend-agnostic `ITelemetryStore` interface with two implementations — `SqliteStore` (local dev/interim) and `PostgresStore` (spec Component 7, schema in `schema.sql`, applied automatically on connect). Selected at runtime via `DNIIP_PG_CONNINFO`.
- **Monitoring** (`server/metrics/`, `monitoring/`): in-process `MetricsRegistry` exposed as `/metrics`, scraped by Prometheus, visualized in a provisioned Grafana dashboard.
- **REST API** (`server/api/`, `dniip-api` binary): read-only JSON API over `ITelemetryStore` for the dashboard — nodes + latest/history telemetry, incidents (filterable by active/resolved), RCA reports. A separate, portable executable from `dniip-server` (no epoll/`/proc` dependency), so it builds and runs on any platform and scales independently of telemetry ingestion. Documented in `docs/api.md`.
- **Dashboard** (`dashboard/`): React + TypeScript + MUI + Chart.js, four pages — Home (node health, active incidents), Nodes (CPU/memory/interfaces/routing, with per-node history charts), Incidents (active/resolved tabs), RCA Reports (view, Export JSON, Download PDF via browser print). Verified running against a live `dniip-api` in a real browser.
- **systemd units** (`scripts/systemd/`): `dniip-agent.service`, `dniip-server.service`, `dniip-api.service` — unprivileged service user, `CAP_NET_RAW` granted only where needed (the agent's raw ICMP socket), `ProtectSystem=strict`.
- **Sample data** (`docs/samples/`): real captured telemetry/incident/RCA-report JSON and a ready-to-use seeded SQLite DB — not hand-written, generated by the actual binaries (see that directory's README for the exact commands).
- **Docs** (`docs/`): `architecture.md`, `protocol.md`, `api.md`, `installation.md`.
- **Tests**: `tests/` GoogleTest suite — 18/18 passing, including a live round-trip against a real local PostgreSQL instance and real HTTP round-trips against both the metrics server and the REST API. `tests/integration/run_integration_test.sh` — a multi-container Docker Compose integration test (requires Docker; not run by `ctest`) asserting agents actually connect, telemetry reaches Postgres, and Prometheus/dashboard/API all serve real data end-to-end.
- **Docker**: full compose stack — `dniip-server`, 2x `dniip-agent`, `postgres`, `prometheus`, `grafana`, `dniip-api`, `dashboard` (nginx).

## Why Docker is required for the agent/epoll server (only)

The agent and epoll-based telemetry server target Linux specifically
(`epoll`, `/proc`, `/sys/class/net`, raw ICMP sockets). On macOS those two
targets are gated out of the native CMake build (see top-level
`CMakeLists.txt`) — everything else, including `dniip-api` and the
dashboard, builds and runs natively on any platform.

## Building natively (everything except dniip-server/dniip-agent)

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH="/opt/homebrew/opt/nlohmann-json;/opt/homebrew/opt/spdlog;/opt/homebrew/opt/sqlite;/opt/homebrew/opt/googletest;/opt/homebrew/opt/libpq"
cmake --build build -j
ctest --test-dir build --output-on-failure
```

The PostgreSQL-backed test (`PostgresStore.SchemaAppliesAndRoundTripsData`)
only runs against a real instance, pointed to via `DNIIP_TEST_PG_CONNINFO`;
it's skipped (not failed) when that's unset:

```sh
brew services start postgresql@16
createdb dniip_test
DNIIP_TEST_PG_CONNINFO="host=localhost dbname=dniip_test" ctest --test-dir build --output-on-failure
```

## Running the dashboard locally without Docker

Seed a local SQLite DB with sample data covering all four correlation
rules, serve it via `dniip-api`, then run the dashboard dev server against it:

```sh
cmake --build build --target dniip-seed-sample-data dniip-api
./build/scripts/dniip-seed-sample-data demo.sqlite
./build/server/dniip-api 8080 demo.sqlite &

cd dashboard
npm install
npm run dev   # opens on http://localhost:5173 (or next free port)
```

## Running the full stack (Linux, via Docker)

```sh
cd docker
docker compose up --build
```

This starts:
- `postgres` — backing store
- `dniip-server` — telemetry port `9000`, metrics port `9100`
- `dniip-agent-a`, `dniip-agent-b` — pointed at `dniip-server:9000`
- `dniip-api` — REST API on port `8080`
- `dashboard` — `http://localhost:3002`
- `prometheus` — `http://localhost:9090`, scraping `dniip-server:9100`
- `grafana` — `http://localhost:3000` (anonymous viewer access enabled), with the DNIIP Overview dashboard pre-provisioned

Watch server logs for `Accepted connection from ...` and any
`Incident ... root_cause=...` lines once correlation rules fire.
